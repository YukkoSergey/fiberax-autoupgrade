# fiberax-autoupgrade (vm-guardian)

Демон для віртуалок [Fiberax](https://fiberax.com): стежить за диском, пам'яттю і процесором, сам
прибирає те, що можна прибрати, а коли ресурсів справді бракує — докуповує їх через
[Fiberax API](https://docs.fiberax.com) у межах заданої власником стелі витрат.

Один файл на Python 3, лише стандартна бібліотека. Працює як systemd-сервіс.

## Що робить

**Диск** (зайнято ≥ 85% або вільно < 6 ГБ):

1. великі текстові логи, яких немає в logrotate, додає в `/etc/logrotate.d/vm-guardian-*` і одразу ротує;
2. чистить кеші: journald, apt/dnf, build-кеш і образи без тегів Docker, кошик і старі версії Nextcloud
   (за його власною політикою), а також теки-кеші, знайдені за ознаками (`cache`, `.cache`, `tmp`,
   `CACHEDIR.TAG`) — лише файли, яких не чіпали понад 30 днів;
3. якщо місця все одно мало і виросли дані з дозволеного списку (`grow_paths`) — лист і +1 ГБ диска;
4. якщо росте щось інше — лише лист: яка тека, чия вона (контейнер, под, сервіс, процес) і на скільки виросла.

**Пам'ять** → +1 ГБ, якщо за 15 хв доступно в середньому < 10%, або тиск пам'яті (PSI) > 10%, або ядро
вбило процес через брак пам'яті на всій машині. Якщо процес убито через ліміт самого контейнера —
лише лист, пам'ять VM не додається.

**CPU** → +1 ядро, якщо середнє завантаження за 30 хв > 85%.

**Гроші.** Перед кожним збільшенням демон рахує місячну вартість VM (за умови, що вона не вимикається)
до і після, перевіряє через API, що збільшення можливе, і порівнює з лімітами:

- вище `warn_eur` — попередження в листі;
- вище `stop_eur` — нічого не додає, шле лист «СТОП» і чекає на `vm-guardian resume`.

**Перезавантаження.** Зміни застосовуються лише в годину найменшого навантаження (з метрик API за
7 днів, в обхід вікна бекапу). Перезавантаження робиться тільки якщо система не побачила нові ресурси.

**Solo та GPU-сервери** (плани й фіксовані пакети): нічого не збільшує, а шле лист власнику зі списком
планів і цін. Автоматичне збільшення працює на Cluster Server.

## Відомий софт

Демон не прив'язаний до конкретної програми: контейнери, томи, процеси, логи й кеші він виявляє сам.
Понад те, для всього, що Fiberax розповсюджує наперед встановленим (WordPress, WooCommerce, Nextcloud, GitLab,
Mailcow, Plesk, aaPanel, бази даних та інше — 27 образів маркетплейсу), є профілі в [`apps.json`](apps.json):
де лежать дані програми, які її логи треба ротувати, які теки можна чистити за віком, які штатні команди
очищення безпечно запускати і що порадити власнику, коли програма росте. Програма розпізнається на машині
за ознаками (файли, сервіси, образи контейнерів), а не за назвою образу, тож профілі працюють і для софту,
поставленого руками.

`vm-guardian apps` показує, що знайдено на машині і чи всі образи каталогу покриті профілями.
Таблиця образів і правила додавання профілю: [docs/marketplace-images.md](docs/marketplace-images.md).

## Встановлення

Потрібні: root, Python 3.9+, systemd, робочий `sendmail` (будь-який MTA), токен Fiberax API з правом запису
(кабінет → API tokens).

```sh
git clone https://github.com/YukkoSergey/fiberax-autoupgrade.git
cd fiberax-autoupgrade
./install.sh
```

Скрипт спитає токен і запустить `vm-guardian setup`, який покаже поточну вартість віртуалки, ціни
наступних апгрейдів і запропонує стелю витрат (більше з «5 апгрейдів CPU» і «+30% від поточної ціни»),
а потім спитає, під які дані можна автоматично докуповувати диск. Поки setup не пройдено, демон лише
моніторить і чистить, але ресурсів не додає.

## Команди

| Команда | Що робить |
|---|---|
| `vm-guardian status` | ресурси, вартість, ліміти, черга, тиха година |
| `vm-guardian setup [--stop EUR] [--warn EUR] [--grow шляхи] [--mail адреса]` | задати ліміти й дозволені дані |
| `vm-guardian allow-growth <тека>` | дозволити докуповувати диск під ці дані |
| `vm-guardian apps` | знайдений відомий софт і покриття каталогу образів профілями |
| `vm-guardian diagnose` | діагностика диска без жодних змін |
| `vm-guardian resume` | зняти стоп після перевищення стелі |
| `vm-guardian test-mail` | перевірити доставку пошти |

Журнал: `journalctl -u vm-guardian`. Налаштування: `/etc/vm-guardian/config.json`
(усі ключі та значення за замовчуванням — у словнику `DEFAULTS` на початку `vm_guardian.py`,
приклад — `config.example.json`). Стан: `/var/lib/vm-guardian/state.json`.

## Листи

- **Звіт про зроблене надсилається завжди.** Якщо демон щось прибрав чи змінив (ротував лог, почистив кеш,
  запланував або виконав збільшення), лист іде щоразу.
- **Однакові тривоги — не частіше ніж раз на добу** (`mail_cooldown_h`). Це стосується повідомлень, де демон
  нічого не зробив: «росте те, під що диск не докуповується», «автозбільшення зупинено», «API недоступний»,
  «процес убито через ліміт контейнера».

## Що чиститься і як це обмежити

Теки-кеші демон знаходить сам: за назвою (`cache`, `.cache`, `tmp`, `*-cache`), за файлом `CACHEDIR.TAG`,
з профілів відомого софту і зі списку `cache_dirs`. Видаляються лише звичайні файли, яких не чіпали понад
`cache_max_age_days` (30) днів, і лише з тек, більших за `cache_min_mb` (200 МБ). Подивитись, що саме буде
зачеплено, нічого не змінюючи: `vm-guardian diagnose`.

Якщо якусь теку чистити не можна — наприклад, там лежать завантажені моделі чи інше, що дорого
отримувати знову, — додай її в `cache_exclude`:

```json
{
  "cache_exclude": ["/root/.cache/huggingface", "/home/build/.cache/bazel"]
}
```

Виняток діє на саму теку і все, що в ній. Після зміни конфігу: `systemctl restart vm-guardian`.

## Чого він не робить

- не видаляє нічого всередині томів контейнерів, `/var/lib` і системних тек;
- не чіпає журнали транзакцій баз даних, навіть якщо вони називаються `*.log`;
- не зменшує ресурси назад;
- не розрізняє навантаження CPU від очікування диска чи steal.

Перевірено на Debian 13 (ext4, Docker, k3s).

## Перевірка на образах

`tools/test_images.py` розгортає сервер з кожного Linux-образу каталогу (чисті ОС і маркетплейс), запускає на ньому
`tools/remote_probe.py` і видаляє сервер. Перевіряється: чи працює скрипт на цьому дистрибутиві, чи розпізнається
софт образу і чи збігаються шляхи профілю з реальними, справжня ротація підробленого лога, справжнє чищення кешів;
з `--resize` — ще й справжнє збільшення диска, пам'яті та ядер через API з перезавантаженням.

**Створює платні сервери й адреси.** Видаляє лише те, що створив сам (список у `<out>/created.json`).
API-токен на тестові сервери не копіюється.

```sh
python3 tools/test_images.py --token /etc/vm-guardian/fiberax.token --out /root/vmg-test \
    --images "Debian 13" --resize "Debian 13"          # один образ, для початку
python3 tools/test_images.py --token /etc/vm-guardian/fiberax.token --out /root/vmg-test --only os
python3 tools/test_images.py --token /etc/vm-guardian/fiberax.token --out /root/vmg-test --only marketplace
python3 tools/test_images.py --token /etc/vm-guardian/fiberax.token --out /root/vmg-test --cleanup   # якщо щось лишилось
```
