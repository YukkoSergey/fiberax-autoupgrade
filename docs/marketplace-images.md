# Образи Fiberax і профілі софту

Каталог зібрано через API (`GET /v1/server-types/{id}/images`, тип Cluster Server; у Solo Server каталог той самий).
Профілі лежать в [`apps.json`](../apps.json). Перевірити покриття на живому каталозі: `vm-guardian apps`.

**Важливо:** API віддає лише назви образів і мінімальні розміри, а не те, як софт розкладений усередині.
Профілі складено за стандартними розкладками кожної програми (нативна установка і Docker), з кількома
варіантами шляхів. На реальних образах маркетплейсу їх ще не перевірено, крім Nextcloud у Docker.

## Як додати профіль

Додати об'єкт у `apps.json`:

- `images` — назви образів каталогу, яким відповідає профіль;
- `detect` — ознаки, за якими програму видно на машині (будь-яка з них): `paths`, `units`, `containers` (регулярні вирази для образу чи імені контейнера), `bins`;
- `data` — теки з даними, під які доречно докуповувати диск (власник підтверджує в `vm-guardian setup`); для контейнерів томи додаються самі;
- `logs` — логи, які мають бути в logrotate;
- `caches` — теки, де можна видаляти файли, старші за `max_age_days`;
- `backups` — власні бекапи програми: не видаляються, лише показуються в листі;
- `cleanup` — штатні безпечні команди очищення (`bin` — потрібна команда, `container` — виконати в контейнері, `foreach` — для кожного знайденого шляху);
- `advice` — підказка власнику, що саме зазвичай росте і як це обмежити.
